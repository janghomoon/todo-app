# README.md 초보자용 설명서

## 이 문서의 목적

[README.md](README.md)는 프로젝트를 처음 접한 사람이 앱의 목적, 실행 방법, 기능과 파일 위치를 파악하는 안내문입니다. 프로그램처럼 직접 실행하는 파일은 아닙니다. 이 설명서는 README의 내용을 [서버 코드](backend/server.py)와 [화면 동작 코드](frontend/js/app.js)에 대조하여 풀어 설명합니다.

## 문서 구조

| 항목 | 알려 주는 내용 | 관련 파일 |
| --- | --- | --- |
| 오늘의 할 일 | HTML/CSS/JavaScript와 Python으로 만든 개인용 로컬 앱이라는 소개 | [화면](frontend/index.html), [서버](backend/server.py) |
| 실행 | Python 버전, 실행 명령, 접속 주소, 종료와 포트 변경 방법 | [서버의 시작 부분](backend/server.py) |
| 기능과 구성 | 추가·완료·삭제 기능과 파일별 역할, 데이터 저장 위치 | [프론트엔드 동작](frontend/js/app.js), [저장 로직](backend/server.py) |
| API 안내 | 화면에서 서버에 요청하는 주소와 방식 | `api()`와 `Handler.route_api()` |

## 실행 명령을 이해하기

프로젝트 폴더에서 다음 명령을 입력합니다.

```sh
python3 backend/server.py
```

`python3`는 Python 실행 프로그램이고 `backend/server.py`는 실행할 파일의 상대 경로입니다. 다른 폴더에서 실행하면 이 상대 경로를 찾지 못할 수 있습니다. 서버는 Python 표준 라이브러리를 사용하므로 별도 패키지 설치 명령이 없습니다. README는 Python 3.9 이상을 요구합니다.

브라우저에 `http://127.0.0.1:8000`을 입력하면 앱 화면을 볼 수 있습니다. `127.0.0.1`은 현재 컴퓨터, `8000`은 서버가 요청을 받는 포트 번호입니다. 터미널의 서버가 실행 중이어야 접속할 수 있으며, 터미널에서 `Ctrl+C`를 누르면 종료됩니다.

```sh
PORT=8001 python3 backend/server.py
```

위 명령은 macOS/Linux 셸에서 이번 실행에 사용할 환경 변수 `PORT`를 지정합니다. 접속 주소도 `http://127.0.0.1:8001`로 바뀝니다. Windows의 명령 프롬프트나 PowerShell은 환경 변수 설정 문법이 다릅니다.

## 파일들의 역할과 실행 흐름

- [frontend/index.html](frontend/index.html): 입력칸, 버튼, 목록 등 화면의 구조를 만듭니다.
- [frontend/css/style.css](frontend/css/style.css): 색, 간격, 화면 너비에 따른 배치 등 모양을 정합니다.
- [frontend/js/app.js](frontend/js/app.js): 사용자 조작을 받아 서버에 요청하고 결과를 화면에 반영합니다.
- [backend/server.py](backend/server.py): 화면 파일을 제공하고 할 일 데이터를 읽거나 저장합니다.
- 각 폴더의 `AGENTS.md`: 개발 작업 지침입니다. 앱이 실행하는 코드가 아닙니다.

실행 흐름은 다음과 같습니다.

1. Python이 `server.py`를 실행하여 `127.0.0.1`에서 요청을 기다립니다.
2. 브라우저가 `/`를 요청하면 서버가 `index.html`을 제공합니다.
3. HTML이 CSS와 JavaScript 파일을 불러옵니다.
4. JavaScript의 `api()`가 HTTP 요청을 보내고, 서버의 `Handler`가 요청 방식에 따라 처리합니다.
5. `route_api()`가 `read_todos()`와 필요한 경우 `save_todos()`를 사용해 데이터를 처리합니다.
6. 서버가 JSON 응답을 보내면 JavaScript의 `render()`가 목록과 완료 개수를 갱신합니다.

JavaScript가 Python 함수를 직접 호출하는 것은 아닙니다. 서로 다른 실행 환경에서 HTTP 요청과 JSON 응답으로 연결됩니다.

## 입력과 출력 예시

아래 결과는 실제 코드에서 도출한 예상 결과입니다. 이 문서 작성 과정에서 서버를 실행해 얻은 기록은 아닙니다.

| 입력 또는 조작 | 예상 결과 |
| --- | --- |
| 기본 실행 명령 입력 | 터미널에 `할 일 앱: http://127.0.0.1:8000` 출력 후 요청 대기 |
| 처음 목록 조회 | 저장 파일이 없으면 빈 목록 `[]` 반환 |
| 입력칸에 `책 읽기` 입력 후 추가 | 완료되지 않은 할 일이 목록에 나타나고 파일에 저장됨 |
| 해당 항목의 체크박스 선택 | 완료 상태가 저장되고 완료 개수가 증가함 |
| 해당 항목의 삭제 버튼 클릭 | 목록과 저장 데이터에서 해당 항목이 제거됨 |

README에 적힌 API는 다음 의미입니다. API는 다른 프로그램이 기능을 요청하는 통로입니다.

| 요청 방식과 주소 | 입력 | 성공 응답 |
| --- | --- | --- |
| `GET /api/todos` | 본문 없음 | `200`, 할 일 배열 |
| `POST /api/todos` | `{"title":"책 읽기"}` | `201`, 생성된 할 일 객체 |
| `PATCH /api/todos/{id}` | `{"completed":true}` | `200`, 변경된 할 일 객체 |
| `DELETE /api/todos/{id}` | 본문 없음 | `200`, `{"ok":true}` |

`{id}`에는 실제 할 일의 고유 식별자를 넣습니다. 생성 응답은 아래 형태이며 `예시-ID`는 설명용 값입니다. 실제로는 서버가 UUID 문자열을 만듭니다.

```json
{"id":"예시-ID","title":"책 읽기","completed":false}
```

공백뿐인 제목을 API로 보내면 `400`과 `{"error":"할 일은 1~200자로 입력해 주세요."}`가 반환됩니다. 완료 상태에는 문자열 `"true"`가 아니라 JSON 불리언 `true`를 보내야 합니다.

## Markdown 핵심 문법

README는 Markdown이라는 문서 작성 형식을 사용합니다.

- `# 오늘의 할 일`: 문서의 큰 제목입니다. `## 실행`처럼 `#`를 두 개 쓰면 하위 제목입니다.
- 줄 앞의 `-`: 기능이나 파일을 나열하는 목록입니다.
- 백틱 하나로 감싼 `backend/server.py`: 경로나 명령 같은 짧은 코드를 본문에서 구분합니다.
- 백틱 세 개로 감싼 영역: 여러 줄 명령을 보여 주는 코드 블록입니다. 뒤의 `sh`는 셸 명령임을 표시하며 자동으로 실행하지 않습니다.

README에는 함수 정의가 없습니다. 실제 주요 함수는 위에서 연결한 JavaScript와 Python 파일에 있습니다.

## 초보자가 헷갈리기 쉬운 부분

- **로컬 앱과 GitHub 저장소:** GitHub에 코드를 올려도 Python 서버가 자동으로 실행되지는 않습니다. README의 명령으로 서버를 실행해야 합니다.
- **저장 위치:** 기본 저장 위치는 서버 쪽 `backend/data/todos.json`입니다. 브라우저의 로컬 저장소에 보관하는 방식이 아닙니다. 코드에서는 `TODO_DATA_FILE` 환경 변수로 경로를 바꿀 수도 있지만 README에는 기본 경로가 안내되어 있습니다.
- **처음에는 저장 파일이 없을 수 있음:** 읽을 때 파일이 없으면 빈 목록을 반환하고, 첫 저장 시 필요한 폴더와 파일을 만듭니다.
- **자동 저장과 Git:** 앱의 저장 데이터는 [.gitignore](.gitignore)에서 제외됩니다. 코드를 push해도 개인 할 일 데이터가 함께 올라가지는 않습니다.
- **개인용 앱:** 사용자 계정이나 사용자별 데이터 분리가 없고 기본 주소도 현재 컴퓨터에서만 접속하도록 설정되어 있습니다.
- **서버 응답과 화면 변화:** 서버는 데이터를 응답합니다. 화면 목록을 다시 그리는 작업은 JavaScript가 맡습니다.

## 확인 범위

README의 실행 명령, 기본 주소와 포트 변경, 파일 역할, 저장 경로, API 종류를 실제 코드와 대조했습니다. 이 설명서 작성으로 원본 코드를 수정하지 않았습니다. 실행 및 브라우저 동작 테스트는 수행하지 않았습니다.
