# 초보자용 코드 설명서 작성

이 스킬은 이 저장소 안의 코드 파일과 모듈을 위한 프로젝트 전용 스킬이다. 원본 코드, 설정, 의존성을 수정하지 않고 설명서만 작성한다. 버그를 발견해도 실제 동작과 주의점을 문서에 설명하고 코드를 고치지 않는다.

## 대상 분석

- 사용자가 지정한 대상과 해당 경로의 `AGENTS.md`를 확인한다. 대상을 문맥에서 결정할 수 없으면 파일 또는 모듈 경로를 묻는다.
- 파일 전체와 이해에 필요한 직접 의존 파일, 호출부, 실행 설정을 읽는다. 이름이나 주석만 보고 동작을 추측하지 않는다.
- 모듈은 진입점, 구성 파일, 내보내는 기능, 내부 호출과 외부 의존 경계를 파악한다. 관련 없는 프로젝트 전체로 분석 범위를 넓히지 않는다.
- 저장소의 `frontend/`는 프론트엔드, `backend/`는 서버와 저장 로직이라는 배치를 실제 코드와 함께 확인한다.

## 설명서 내용

제목과 설명은 한국어로 작성하고 실제 식별자와 경로는 그대로 표기한다. 전문 용어는 처음 나올 때 쉬운 뜻을 덧붙인다. 다음 내용을 대상에 맞게 구성한다.

- **목적과 범위:** 해결하는 문제, 앱 안에서 맡은 역할, 분석한 파일과 진입점.
- **구조:** 파일 내부의 주요 구성. 모듈이면 파일별 역할을 표로 정리하고, `진입 파일 → 호출 함수 → 다른 파일의 함수`처럼 실제 호출 관계를 보여 준다. 단순 import 관계와 실행 시 호출 관계를 구분한다. HTTP 요청이나 이벤트를 통한 연결은 그 방식을 명시한다.
- **실행 흐름:** 시작 조건부터 입력 처리, 함수 호출, 상태 변경 또는 저장, 결과 반환·화면 반영까지 순서대로 설명한다. 비동기 처리와 주요 오류 분기가 있으면 포함한다.
- **주요 함수:** 실제 함수명, 역할, 인자, 반환값, 부수 효과와 호출 위치를 설명한다. 반환값이 없으면 없다고 적고 화면 갱신이나 파일 저장과 구분한다.
- **핵심 문법:** 대상에 실제 등장하고 이해에 중요한 문법을 짧은 코드 인용과 함께 설명한다. 전체 코드를 복사하거나 코드에 없는 일반 문법 강의를 덧붙이지 않는다.
- **입출력 예시:** 입력과 전제 상태, 호출 또는 사용자 조작, 예상 반환값·응답·화면·저장 결과를 짝지어 제시한다. 해당하는 경우 빈 입력이나 오류 예시도 포함한다. 임의 예시 데이터와 실행 결과를 구분하고, 실행하지 않은 결과는 코드에서 도출한 예상 결과라고 표시한다.
- **헷갈리기 쉬운 부분:** 실제 코드에서 혼동할 만한 변수 범위, 데이터 형태, 비동기 순서, 반환과 출력의 차이 등을 이유와 함께 설명한다. 해당하지 않는 항목은 억지로 넣지 않는다.

핵심 설명에는 상대 경로 링크와 함수명 등 다시 찾아볼 수 있는 근거를 남긴다. 외부 라이브러리 내부 구현이나 확인하지 못한 동작을 단정하지 않는다.

## 저장 규칙

- 단일 파일은 마지막 확장자를 뺀 이름을 사용해 같은 폴더에 `[이름]-guide.md`로 저장한다. 예: `frontend/js/app.js` → `frontend/js/app-guide.md`.
- 폴더 단위 모듈은 모듈 폴더 안에 `[폴더명]-guide.md`로 저장한다. 예: `backend/` → `backend/backend-guide.md`. 여러 파일로 된 모듈은 파일마다 문서를 만들기보다 관계를 설명하는 하나의 문서로 정리한다.
- 같은 이름의 기존 설명서가 있으면 먼저 읽고 해당 대상의 설명을 갱신한다. 다른 대상을 위한 문서와 경로가 충돌하면 확장자를 포함한 이름(예: `app.js-guide.md`)으로 구분한다.

## 완성 후 확인

설명서를 저장한 뒤 실제 코드와 다시 대조한다. 함수명·인자·반환값, 파일 간 호출 방향, 실행 순서, 오류 처리, 예시의 입력과 결과가 일치하는지 확인하고 어긋난 설명을 고친다. 링크 경로와 저장 위치도 확인한다.

정적 분석으로 충분하면 코드를 실행하지 않아도 된다. 실행 검증이 필요할 때는 기존의 안전한 테스트나 격리된 임시 데이터를 이용하고 실제 저장 데이터나 외부 서비스에 영향을 주는 실행을 피한다. 실행하지 않은 검증을 수행했다고 표현하지 않는다.

최종 변경 내역을 확인하여 이 작업으로 원본 코드가 바뀌지 않았는지 점검한다. 기존 사용자 변경은 되돌리지 않는다. 완료 응답에는 설명서 링크와 검증 방식, 남은 불확실성이 있으면 그 내용을 간단히 알린다.
